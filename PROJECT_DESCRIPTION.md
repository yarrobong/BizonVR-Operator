# BizonVR Club Control — описание проекта

> Статус документа: продуктовый scope и MVP-намерения. Фактический runtime
> репозитория описан в [README](README.md),
> [текущей архитектуре](docs/architecture.md) и
> [portfolio summary](docs/portfolio-summary.md). Упомянутые ниже планы не
> являются заявлением о физической Quest E2E-проверке или production rollout.

## 1. Кратко

**BizonVR Club Control** — подписочная система управления Meta Quest-шлемами для VR-клубов. Она объединяет карту клуба, запуск игр, режим игровых сессий, трансляцию через scrcpy, установку APK одной кнопкой, мониторинг устройств и контроль подписки.

Цель MVP — дать оператору клуба возможность управлять всеми Quest-шлемами из одной панели, не бегая к каждому устройству вручную.

## 2. Целевая аудитория

- VR-клубы на Meta Quest 2 / Quest 3 / Quest 3S / Quest Pro.
- VR-арены и аттракционы.
- Владельцы клубов, которым нужен контроль парка устройств.
- Операторы, которым нужно быстро запускать сессии.
- Сети клубов, которым нужна единая панель по нескольким филиалам.

MVP делается **только под Meta Quest**. Pico, PCVR и SteamVR не входят в первую версию.

## 3. Главная ценность

Продукт должен решать реальные боли клуба:

- быстро запускать нужную игру на нужных шлемах;
- видеть, где какой шлем лежит;
- понимать, какой шлем сел, оффлайн или потерял ADB;
- ставить игры и обновления на группу шлемов;
- смотреть трансляцию со шлема через scrcpy;
- вести сессии по таймеру;
- помогать оператору не забывать про протирку, зарядку и обслуживание;
- давать владельцу историю действий и понимание загрузки клуба.

## 4. Основные компоненты

### Cloud SaaS

В текущем репозитории Cloud/API реализован как Node.js + Express + TypeScript
процесс с `better-sqlite3`. Он хранит клубы, пользователей, подписки,
устройства, комнаты, игровые сессии, библиотеку APK, логи и monitoring state.
PostgreSQL, Redis и Django остаются вариантами будущего hosted deployment, а
не текущими runtime-зависимостями.

### Web Operator Panel

Веб-панель для оператора, администратора и владельца. Главный экран — **карта клуба**.

### Local Hub

Node.js-программа на компьютере клуба. Она находится в одной локальной сети
со шлемами и выполняет технические действия: ADB, scrcpy, установка APK,
запуск/закрытие приложений, локальное кеширование и отправка статусов в API.
Electron/Tauri-обёртка и production-пакетирование в репозитории не заявлены.

### Quest Agent

Android-приложение на шлеме. Оно отвечает за идентификацию устройства, heartbeat, сообщения игроку, кнопку вызова оператора и Club Launcher.

Текущий production path в коде — `quest-agent-spatial-spike` с package
`com.bizonvr.spatialspike`; историческое имя проекта сохранено, чтобы не
вносить лишний Gradle/package churn.

### Club Launcher

Клубное меню на Quest, **без Unity**. Делается как нативное Android-приложение на Kotlin/Java. В MVP это soft launcher: экран ожидания, таймер сессии, сообщения, список разрешённых игр и кнопка вызова оператора.

## 5. Главный сценарий: режим сессии

Оператор выбирает комнату, игру, шлемы и длительность. Система делает pre-flight check:

- Local Hub онлайн;
- шлемы онлайн;
- ADB доступен;
- Quest Agent доступен;
- заряд выше порога;
- есть свободная память;
- нужная игра установлена;
- нет конфликта с другой сессией;
- scrcpy доступен, если нужна трансляция.

После старта система:

1. переводит шлемы в статус `in_session`;
2. закрывает лишние приложения;
3. запускает выбранную игру;
4. включает таймер;
5. показывает live-статусы на карте;
6. даёт открыть scrcpy-трансляцию;
7. предупреждает за 5 минут до конца;
8. по завершении закрывает игру;
9. возвращает шлем в Club Launcher;
10. создаёт чеклист обслуживания.

## 6. Карта клуба

Карта клуба показывает комнаты, зоны и устройства. На ней видно:

- свободна или занята комната;
- какая игра запущена;
- сколько осталось времени;
- заряд каждого шлема;
- проблемы;
- быстрые действия: старт, продлить, завершить, открыть трансляцию.

Карта должна быть не просто красивой схемой, а рабочим центром оператора.

## 7. Мониторинг

Система отслеживает:

- online/offline;
- battery level;
- charging status;
- свободную память;
- ADB status;
- Agent status;
- текущую игру;
- ошибки установки;
- ошибки scrcpy;
- состояние Local Hub;
- устаревшие версии игр.

Алерты: `info`, `warning`, `critical`, `blocker`.

## 8. Установка APK одной кнопкой

Админ загружает APK в библиотеку. Система извлекает package name, версию, размер и checksum. После этого игру можно установить на один шлем, комнату или группу устройств.

Важно: продукт должен работать только с легальным контентом, на который у клуба есть права.

## 9. Трансляция через scrcpy

В текущем MVP оператор открывает трансляцию прямо в веб-панели. Cloud API отдаёт адрес Local Hub, после чего браузер подключается к локальному stream endpoint, а сам Local Hub получает кадры по ADB внутри клуба.

Cloud по-прежнему не подключается к Quest напрямую и не выполняет scrcpy/ADB сам.

## 10. Подписочная модель

Названия тарифов ниже — продуктовая модель. В текущем seed/runtime проверяются
активная подписка, feature flags и лимит устройств; биллинг и payment
интеграция в репозитории не реализованы.

Тарифы можно строить по количеству устройств и функциям:

- **Start** — до 5 шлемов, базовое управление, сессии, мониторинг.
- **Club** — до 20 шлемов, карта, пакеты APK, scrcpy, история, роли.
- **Pro** — 50+ шлемов, филиалы, API, автообновления, white-label launcher.
- **Enterprise** — индивидуальные лимиты, SLA, интеграции.

## 11. Ограничения

- Quest должен быть подготовлен для ADB.
- Для scrcpy нужен ADB-доступ.
- Для wireless ADB может потребоваться первичная USB-настройка.
- Полный kiosk/lockdown может быть ограничен на consumer Quest.
- Cloud не должен подключаться к шлемам напрямую: все локальные действия делает Local Hub.
- Нельзя обещать установку любых игр из Meta Store без прав и официальной модели распространения.

## 12. MVP

В MVP входит:

- регистрация клуба;
- роли Owner/Admin/Operator/Technician;
- Local Hub для Windows;
- Quest Agent APK;
- onboarding Quest через USB/ADB;
- список устройств;
- карта клуба;
- мощный режим сессии;
- запуск/закрытие игр;
- установка APK;
- scrcpy отдельным окном;
- мониторинг и алерты;
- подписочные лимиты;
- audit log.
