# Stage 2 security boundary

The Web API accepts signed `Authorization: Bearer` tokens generated by the
small HMAC token helper. Production requires `AUTH_SECRET` to be a random value
of at least 32 characters. The token subject is resolved against the active user
record, organization, and club scope in SQLite; `x-user-id` is ignored unless
`ALLOW_DEV_AUTH_FALLBACK=1` is explicitly enabled outside production.

Cloud-to-Hub requests use `HUB_TOKENS_JSON` with one credential per Hub. A
single `HUB_TOKEN` is retained only for local/single-Hub compatibility. Secret
comparisons are constant-time and Hub IDs are checked against the credential
being used. A missing Hub token is rejected unless the explicitly named
`ALLOW_DEV_HUB_AUTH_FALLBACK=1` is enabled outside production.

Quest Agent requests use a pairing-bound credential provisioned by the pair or
install command. It is passed in the HTTP Authorization header, stored as a
hash in Cloud, and never returned by inventory, command, or audit list APIs.
The Local Hub also requires a fresh Agent timestamp (default one minute) and
rejects non-monotonic heartbeat timestamps. This limits stale heartbeat replay;
full signed nonce protocol and an independent revocation list are intentionally
deferred until a protocol versioning task. Re-pair/install-agent generates a
new credential, overwrites the Cloud hash and the Hub's 0600 local credential
record, and therefore invalidates the previous credential in that Hub. There
is no separate cross-Hub revocation list yet.

APK installs resolve only `artifact_id` values under the approved Local Hub
cache and verify the SHA-256 before invoking ADB. The generic Cloud JSON body
limit is 64 KiB; Agent JSON is 32 KiB. ADB output is bounded to 1 MiB stdout /
256 KiB stderr for text and 8 MiB for binary screencap output.
